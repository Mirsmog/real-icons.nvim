==============================================================================
INTRODUCTION                                          *real-icons-introduction*

real-icons.nvim renders file and folder icons as real terminal images. It uses
Kitty Graphics Protocol Unicode placeholders, supports Ghostty and Kitty, and
can fall back to glyph icon providers such as mini.icons or nvim-web-devicons.

It provides real image icons in terminal UI rows, SVG icon pack rasterization,
VS Code icon theme support, custom local packs, and opt-in integrations for
popular Neovim UI plugins.

==============================================================================
REQUIREMENTS                                          *real-icons-requirements*

- Neovim 0.10+
- Ghostty or Kitty
- termguicolors
- ImageMagick for SVG icon packs and color transforms
- curl and tar for pack installation

tmux requires passthrough:
>
  set -g allow-passthrough on
<

==============================================================================
SETUP                                                        *real-icons-setup*

Example lazy.nvim spec:
>
  {
    "Mirsmog/real-icons.nvim",
    build = ":RealIcons install",
    opts = {
      integrations = {
        telescope = true,
      },
    },
  }
<

Full configuration:

The explicit pack field below takes priority over a theme saved in the picker.
Omit it to use the saved selection, or Material when no selection is saved.
>
  require("real-icons").setup({
    pack = "material",
    packs = {},
    overrides = {},
    rules = {
      directories = {},
    },
    backend = "auto",
    size = {
      cols = 2,
      rows = 1,
      pixels = 64,
      padding = 0,
      trim = false,
      density = "auto",
      oversample = 1.25,
    },
    color = {
      tint = nil,
      saturation = 0,
      brightness = 0,
      hue = 0,
      monochrome = false,
    },
    fallback = {
      enabled = true,
      provider = "auto",
    },
    integrations = {
      bufferline = false,
      fzf_lua = false,
      lualine = false,
      mini_files = false,
      neo_tree = false,
      nvim_tree = false,
      oil = false,
      snacks_picker = false,
      telescope = false,
      telescope_file_browser = false,
    },
  })
<

Icon sharpness:
>
  require("real-icons").setup({
    size = {
      cols = 2,
      rows = 1,
      pixels = 64,
      padding = 0,
      trim = false,
      density = "auto",
      oversample = 1.25,
    },
  })
<

backend = "auto" detects Kitty Graphics Protocol compatible terminals.
backend = "kitty" forces the Kitty Graphics Protocol renderer, and
backend = "disabled" forces glyph fallback.

cols and rows reserve terminal cells. rows currently must be 1. pixels controls
the generated PNG size. If a pack has too much transparent padding, set
trim = true. If icons look too large after trimming, add padding.

density = "auto" reads each SVG view box and chooses a suitable raster density
with oversample headroom. Set density to a number such as 384 to force a fixed
raster density.

WEZTERM ~

WezTerm supports the base Kitty Graphics Protocol but does not currently
support Kitty Unicode placeholders (U=1), which real-icons needs to attach an
image to a Neovim grid cell. backend = "auto" detects WezTerm and safely uses
glyph fallback. See https://github.com/wezterm/wezterm/issues/986.

Color transforms are applied while building the PNG cache:
>
  require("real-icons").setup({
    color = {
      saturation = -100,
    },
  })
<

Use tint to replace icon colors while preserving alpha:
>
  require("real-icons").setup({
    color = {
      tint = "#89b4fa",
    },
  })
<

brightness, saturation, and hue are percentage offsets where 0 is neutral.
Aliases are also accepted: lightness for brightness, mask and mask_color for
tint, and grayscale for monochrome. A string value such as color = "#89b4fa"
is treated as a tint.

==============================================================================
ICON PACKS                                                  *real-icons-packs*

Install the default Material Icon Theme pack:
>
  :RealIcons install
<

The plugin stores installed packs under stdpath("data")/real-icons/packs and
generated PNG files under stdpath("cache")/real-icons.

Discover, preview, and switch packs at runtime:
>
  :RealIcons packs
<

Lua API:
>
  require("real-icons").use_pack("material")
<

Switching packs clears uploaded terminal image ids, refreshes existing
real-icons extmarks and supported integrations, and emits:
>
  User RealIconsPackChanged
<
The coalesced User RealIconsUpdated event also fires for cache readiness and
colorscheme changes. Longest extension matches win: widget.test.ts can use a
different icon from widget.ts. Light theme and expanded folder associations
are respected when supplied by a VS Code theme.

Custom VS Code icon theme:
>
  require("real-icons").setup({
    pack = "flow",
    packs = {
      flow = {
        type = "vscode",
        path = vim.fn.expand("~/.vscode-oss/extensions/thang-nm.flow-icons-2.0.3"),
        theme = "flow-deep",
      },
    },
  })
<

Simple local icon folder:
>
  require("real-icons").setup({
    pack = "my-icons",
    packs = {
      ["my-icons"] = {
        type = "simple",
        path = "~/icons",
        file = "file.svg",
        folder = "folder.svg",
        extensions = {
          lua = "lua.svg",
          ts = "typescript.svg",
        },
        filenames = {
          ["package.json"] = "nodejs.svg",
        },
        folders = {
          src = "folder-src.svg",
        },
      },
    },
  })
<

Discover and preview local VS Code icon themes:
>
  :RealIcons packs
<

The picker scans common VS Code-compatible extension directories, registers
found icon themes for the current Neovim session, and previews sample file icons
before switching packs.

Overrides:
>
  require("real-icons").setup({
    overrides = {
      extensions = {
        lua = "~/icons/custom-lua.svg",
      },
      filenames = {
        [".env"] = "~/icons/env.svg",
      },
      folders = {
        node_modules = "~/icons/node_modules.svg",
      },
    },
  })
<

Directory path rules:
>
  require("real-icons").setup({
    rules = {
      directories = {
        {
          glob = "**/src/*/scala/**",
          icon = "folder-packages",
        },
      },
    },
  })
<

Directory rules match normalized full paths and are evaluated in order. The
first match with an icon available in the active pack wins. * matches within
one path segment and ** can cross path separators. Exact folder overrides take
precedence. If a rule icon is unavailable, normal folder resolution continues.
The icon value may also be a path to a PNG or SVG file.

INTEGRATIONS                                        *real-icons-integrations*

All integrations are opt-in.

Telescope core file pickers:
>
  require("real-icons").setup({
    integrations = {
      telescope = true,
    },
  })
<

This affects Telescope file pickers that use telescope.make_entry.gen_from_file,
including oldfiles, find_files, and git_files.

telescope-file-browser.nvim:
>
  require("telescope").setup({
    extensions = {
      file_browser = {
        entry_maker = require("real-icons.integrations.telescope_file_browser").entry_maker,
      },
    },
  })
  require("telescope").load_extension("file_browser")
<

The adapter wraps the extension's upstream entry maker. Caching,
multi-selection, git and stat columns, and resize handling stay upstream.

fzf-lua:
>
  require("real-icons").setup({
    integrations = {
      fzf_lua = true,
    },
  })
<

Manual fzf-lua setup:
>
  require("fzf-lua").setup(require("real-icons.integrations.fzf_lua").opts())
<

The adapter preserves the configured fzf-lua layout and search pipeline. It
reserves an icon slot and renders only entries visible in the embedded fzf
window. Native fzf-tmux windows cannot display Neovim extmarks and keep the
lightweight fallback slot.

oil.nvim:
>
  require("real-icons").setup({
    integrations = {
      oil = true,
    },
  })
<

The adapter replaces Oil's native icon column renderer and does not scan the
buffer on text changes.

nvim-tree.lua:
>
  require("real-icons").setup({
    integrations = {
      nvim_tree = true,
    },
  })
<

Current nvim-tree releases use the public Decorator API. Older releases use a
legacy renderer fallback. Other nvim-tree decorators remain unchanged.

neo-tree.nvim:
>
  require("real-icons").setup({
    integrations = {
      neo_tree = true,
    },
  })
<

Manual neo-tree setup:
>
  require("neo-tree").setup(require("real-icons.integrations.neo_tree").opts())
<

mini.files:
>
  require("real-icons").setup({
    integrations = {
      mini_files = true,
    },

<

Manual mini.files setup:
>
  require("mini.files").setup(require("real-icons.integrations.mini_files").opts())

bufferline.nvim:
>
  require("real-icons").setup({
    integrations = {
      bufferline = true,
    },
  })
<

Manual bufferline setup:
>
  require("bufferline").setup(require("real-icons.integrations.bufferline").opts())
<

lualine.nvim:
>
  require("real-icons").setup({
    integrations = {
      lualine = true,
    },
  })
<

The automatic icon component leaves filename padding to lualine. Unnamed,
special and URI-based buffers do not receive a file icon. Passing an explicit
path or filetype to component() overrides this guard.

For a global statusline that keeps the file context while a popup or sidebar
has focus, configure lualine's ignore_focus option:
>
  require("lualine").setup({
    options = {
      globalstatus = true,
      ignore_focus = function(win)
        return vim.api.nvim_win_get_config(win).relative ~= ""
          or vim.bo.buftype ~= ""
      end,
    },
  })
<

Manual lualine component:
>
  require("lualine").setup({
    sections = {
      lualine_c = {
        require("real-icons.integrations.lualine").component,
        "filename",
      },
    },
  })
<

snacks.picker:
>
  require("real-icons").setup({
    integrations = {
      snacks_picker = true,
    },
  })

==============================================================================
API                                                            *real-icons-api*

Get an icon:
>
  local icons = require("real-icons")
  local text, hl, is_default, meta = icons.get("file", "init.lua")
<

icons.get() requires an explicit category; path-only shorthand is not
supported.

Supported categories:
>
  icons.get("file", "init.lua")
  icons.get("directory", "src")
  icons.get("extension", "lua")
  icons.get("filetype", "lua")
<

icons.icon() and icons.get_icon() are aliases for icons.get().

For text-based hooks, use segment() when width or metadata is needed:
>
  local icons = require("real-icons")
  local segment = icons.segment("file", "init.lua")
  return segment.text, segment.hl
<

Cold images are converted in the background, with at most two conversion
processes at once. segment.pending and get()'s meta.pending are true while a
fallback reserves the icon slot. Built-in integrations refresh automatically.
Custom text integrations should redraw on User RealIconsUpdated and recompute
their segments; do not retain an old segment across that event. It is coalesced
and fires after cache preparation, pack changes, and colorscheme changes.

Pass { async = false } as the final options argument if a script needs to wait
for one image. build_cache() remains a synchronous bulk operation.

Render an icon into a buffer-based UI:
>
  icons.render(bufnr, row, col, "file", "init.lua")
<

Advanced integrations can resolve the engine object directly:
>
  local icons = require("real-icons")
  local icon = icons.resolve("file", "init.lua")
  icons.render(bufnr, row, col, icon)
<

List configured mappings:
>
  local icons = require("real-icons")
  vim.print(icons.categories())
  vim.print(icons.list("extension"))
<

Check capabilities:
>
  local icons = require("real-icons")
  if icons.is_supported() then
    print(icons.backend())
  end
  vim.print(icons.capabilities())
<

Switch icon packs:
>
  local icons = require("real-icons")
  icons.use_pack("material")
  icons.use_pack("material", { save = true }) -- Also save the default
  print(icons.pack())
  vim.print(icons.available_packs())
<

Saved choices are stored under stdpath("state")/real-icons/selection.json.
Explicit setup({ pack = "..." }) options take priority. Saving a custom local
theme also saves its pack specification, without rewriting the user's config.
Delete selection.json to forget the saved default.

Inspect or retry enabled integrations:
>
  vim.print(icons.integration_status())
  icons.retry_integrations()
<
Status is ready, waiting, manual, error, or disabled. A manual status means the
Telescope file browser entry_maker hook still needs to be configured; it is not
verified automatically. Dependency errors include details. LazyLoad retries
pending integrations automatically.

Install without blocking an interactive session:
>
  icons.install_pack("material", {
    async = true,
    on_complete = function(ok, err)
      if not ok then vim.notify(err) end
    end,
  })
<
Without async = true, install_pack() waits for completion. A failed asynchronous
start returns false and an error immediately; on_complete handles a job that
was accepted. Failed downloads or invalid manifests preserve the installed pack.

==============================================================================
COMMANDS                                                  *real-icons-commands*

:RealIcons
  Show renderer, terminal, pack, and integration status. Keys: p themes,
  d demo, i install, h health, r retry integrations, y copy diagnostics,
  ? help, q or <Esc> close.

:RealIcons demo
  Open a renderer preview.

:RealIcons packs
  Discover and preview configured packs and compatible local editor themes.
  j/k or arrows browse; / filters; <Enter> applies for this session; s applies
  and saves the default; y copies pack configuration; i installs Material;
  q or <Esc> closes. Missing or invalid packs cannot be applied in the picker.

:RealIcons install [name]
  Install Material Icon Theme. Omit [name] or pass material.
  Runs in the background with a UI attached; waits in headless builds.

:RealIcons health
  Run :checkhealth real-icons.

:RealIcons report
  Copy renderer and integration diagnostics to the clipboard, or to the unnamed
  register if no clipboard provider is available. Paste from the register with p.

:RealIcons help
  Open this help page.

:RealIcons clear-cache [name]
  Clear generated cache files for one pack or every pack. Cache variants are
  selected automatically, so this is normally only needed for recovery.

All actions and arguments support command-line completion.

==============================================================================
TROUBLESHOOTING                                    *real-icons-troubleshooting*

Run :RealIcons health first. It checks terminal support, termguicolors,
ImageMagick, tmux passthrough, the active icon pack, and enabled integration
status. :RealIcons report collects a short text report for issue discussions.

If icons do not appear:
- Confirm you are running inside Ghostty or Kitty.
- Confirm termguicolors is enabled.
- Install the default pack with :RealIcons install.
- Run :RealIcons demo outside tmux, then inside tmux.
- In tmux, confirm set -g allow-passthrough on is loaded.

If icons are blurry:
- Keep SVG packs as sources when possible.
- Increase size.pixels.
- Use cols = 2 for one-row icons.

Cache paths include size, density, padding, and color settings. Changing those
options automatically creates a new variant without a manual rebuild. Source
paths and modification times are included so replaced theme assets are not
mistaken for older cached files. Failed conversions can be retried with
:RealIcons clear-cache.
